# Айболит — фронтенд (шаг 3: проверка документов, живой таймер курьера, магазин)

Статический прототип на HTML/CSS/JS, данные — в `localStorage` браузера
(backend ещё впереди). Локально: `npm start` (или Live Server на папке `public/`).

## Последние правки
- **Фото товаров меняет только админ.** Форма загрузки убрана из магазина; в `admin.html` появился раздел «Товары магазина» (загрузить / заменить / убрать фото). Клиент, ветеринар, курьер и няня видят готовые фото, но менять их не могут (защита есть и в `updateProductImage`).
- **Мои питомцы (клиент):** фото можно поставить и заменить у уже добавленного питомца (клик по кружку с 📷), кличку и вид — менять через ✎. Исправлена ошибка порядка объявления переменных в `profile.js`, из-за которой раздел питомцев ломался.
- Все загружаемые фото сжимаются (`fileToResizedDataUrl`), чтобы не упираться в лимит localStorage.

## Новое в этой версии

### 1. Проверка документов администратором
- При регистрации **ветеринар / курьер / няня** прикладывают документы
  (удостоверение личности, сертификат/права/техпаспорт) — они реально
  сохраняются (как base64) и видны админу.
- После регистрации такой пользователь попадает не в ленту, а на
  экран **"Документы на проверке"** (`pending.html`) — доступ к сайту
  закрыт, пока админ не одобрит.
- **Клиент** проверку не проходит — доступ открывается сразу.
- **Вход администратора** — на `login.html` кнопка **«Другое»** под
  формой входа открывает отдельную форму: логин `admin`, пароль
  `qwerty2202`. Неверные данные — обратно на главную.
- `admin.html` — список заявок на проверку: анкета, фото документов
  (кликабельны, открываются в полный размер), кнопки **Одобрить** /
  **Отклонить**.
- Одобрили — при следующей проверке статуса пользователь сам
  попадает в ленту. Отклонили — видит экран **"Вы заблокированы"**
  (`blocked.html`).
- Админ видит только тех, кто зарегистрирован **на этом устройстве**
  (это ограничение localStorage-демо — с backend админ увидит всех
  пользователей сразу, а не только "локальных").

### 2. Заказы: настоящий таймер курьера + карта-прогресс
- Курьер берёт заказ и **указывает своё время до точки А** (в минутах).
  Обратный отсчёт — по настоящим часам (`Date.now()`), а не просто
  секундомер: переживает перезагрузку страницы.
- Когда время истекло — курьер вводит **время до точки B**, и едет
  второй отрезок пути.
- **Клиент и ветеринар видят тот же таймер и мини-карту прогресса**
  (полоса с двумя точками А/Б и бегущим маркером) на странице «Заказы»
  — это и есть "наблюдение за курьером", которое вы просили. Карта
  визуальная (не настоящее GPS с телефона курьера — для реального
  местоположения нужен backend + доступ к геолокации устройства),
  но синхронизирована с реальным временем и одинакова у всех, кто
  смотрит эту заявку.
- Список заказов и таймеры обновляются каждую секунду и сразу же
  подхватывают изменения, сделанные в другой вкладке того же браузера.

### 3. Магазин
- У каждого товара теперь своя иконка по категории (SVG, без внешних
  картинок — не зависит от интернета).
- Корзина — теперь полноценная панель: видно все товары, можно
  менять количество (+/-), убирать товар, видна итоговая сумма и
  кнопка «Оформить заказ». На телефоне открывается выезжающей панелью
  по кнопке корзины.

### 4. Общая доработка дизайна
- Добавлены тени и более выраженные карточки — меньше "пустых" плоских
  зон, особенно на десктопе.
- Правая колонка (`aside`) страниц теперь либо используется по делу
  (корзина в магазине), либо остаётся содержательной.
- Поправлена мобильная адаптация: нижняя панель вкладок, гамбургер-меню
  на лендинге, корзина как выезжающая панель.

## Как посмотреть сценарий "клиент → курьер → ветеринар" целиком
Поскольку backend ещё не подключён, все роли живут в одном браузере —
переключайтесь между ними через **"Сменить аккаунт"** в сайдбаре:
1. Зарегистрируйтесь как **клиент**, создайте заявку на доставку.
2. Через переключатель аккаунтов зарегистрируйте **курьера** (или
   переключитесь на уже созданного) — но сначала его должен одобрить
   админ (см. выше).
3. Как админ (через "Другое" на `login.html`) одобрите курьера.
4. Переключитесь на курьера, возьмите заказ, укажите время — увидите
   отсчёт и карту.
5. Переключитесь обратно на клиента — на странице «Заказы» будет
   виден тот же самый таймер и карта.

## Деплой на Vercel
Проект — чистая статика, сборка не нужна. `vercel.json` указывает `outputDirectory: public`.

**Через GitHub (рекомендуется):**
1. Залейте папку в репозиторий (корень репозитория = папка с `vercel.json`).
2. На vercel.com → *Add New → Project* → выберите репозиторий.
3. Framework Preset — **Other**; Build Command и Install Command оставьте пустыми; Output Directory — `public` (подхватится из `vercel.json`). Нажмите *Deploy*.

**Через CLI:**
```bash
npm i -g vercel
vercel        # превью
vercel --prod # продакшен
```

Что изменено под Vercel: ссылки и пути к ресурсам стали абсолютными (`/css/style.css`, `/feed`), включены clean URLs (`/feed` вместо `/feed.html`), добавлены `404.html`, favicon и security-заголовки.

**Важно про localStorage:** данные живут в браузере и привязаны к домену. У каждого preview-деплоя (и у `*.vercel.app` vs. своего домена) свой адрес — значит, своя «база». Пользователи, админ-заявки и заказы не переносятся между доменами и устройствами, пока нет backend.

## Дальше — backend
Всё то же самое: каждая функция `store.js` (включая новые —
`acceptDelivery`, `approveAccount`, `getPendingAccounts`) станет
эндпоинтом Spring Boot. Админ-панель и таймер курьера особенно
выиграют от backend: админ увидит всех пользователей сразу, а таймер
курьера станет настоящим GPS-треком через WebSocket.
